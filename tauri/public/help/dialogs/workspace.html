Workspace

Workspace は、保存済みオプションや設定ファイルを置く作業ディレクトリです。ヘッダの ChangeWorkspace ボタンからダイアログを開いて切り替えます。このページでは、ChangeWorkspace の入力項目、Workspace のディレクトリ構成、Workspace を基準に動くサイドバー・フッター・ファイル選択の挙動を説明します。Workspace を選んでから実行・保存・再利用するまでの流れは 基本的な使い方 を参照してください。

ChangeWorkspace の入力項目

項目説明デフォルト
Workspace（必須）作業ディレクトリ。存在しない場合は作成する。%USERPROFILE% / %HOME% を使える起動ディレクトリ
Dataset Baseデータセット（入力ファイル）を相対パスで指定したときの基準ディレクトリWorkspace
Result Base出力先を相対パスで指定したときの基準ディレクトリWorkspace
Env環境変数ファイル（.properties）のパス。Workspace からの相対パス（絶対パスも可）。ファイル選択で Workspace 配下を選ぶと相対パスに変換される。空欄にするとデフォルトに戻るenv.properties

Workspace を変更すると、Workspace で始まる Dataset Base / Result Base は新しい Workspace に合わせて書き換わります。

Workspace のディレクトリ構成

<workspace>/
├── env.properties             環境変数ファイル（デフォルト）
├── option/
│   ├── <command>/             コマンドごとの保存済みオプション
│   └── parameterize/template/ Parameterize 用テンプレート
└── resources/
    ├── setting/               Dataset Settings
    ├── template/              テンプレート
    ├── jdbc/                  JDBC 接続設定
    ├── xlsxSchema/            Xlsx Schema
    └── fixed-column-def/      固定長カラム定義

各入力欄でファイル名だけ指定した場合は、対応するディレクトリ、Workspace の順に探します。

Workspace の影響範囲

Workspace を切り替えると、次の画面要素が新しい Workspace の内容に切り替わります。どのボタンがどこを読み書きするかは サイドバー と フッター を参照してください。

画面要素読み書きする場所
サイドバーoption/<command>/*.txt（保存済みオプションの一覧）
フォームの各設定ダイアログresources/ 配下（Dataset Settings・テンプレート・JDBC・Xlsx Schema・固定長カラム定義）
フォームの相対パス入力ファイルは Dataset Base、出力先は Result Base、それ以外は Workspace を基準に解決
Exec / Save ShellEnv ファイル（${env.変数名} の置き換え）

ファイル選択と Workspace

フォームでオプションを組み立てるとき、入力欄の横のファイル選択・ディレクトリ選択ボタンは、オプションごとに決まった基準ディレクトリを使います。基準ディレクトリは ChangeWorkspace の設定で決まるので、Workspace / Dataset Base / Result Base を切り替えると、選択ダイアログの開く場所と相対パスの意味も変わります。

オプションごとの基準ディレクトリ

項目基準ディレクトリ
-src（入力データ）Dataset Base
-result（出力先）Result Base
-setting / -unitSetting<workspace>/resources/setting
-template（Generate）/ -templateGroup<workspace>/resources/template
-template（Parameterize）<workspace>/option/parameterize/template
-jdbcProperties<workspace>/resources/jdbc
-xlsxSchema<workspace>/resources/xlsxSchema
-fixedColumnDef<workspace>/resources/fixed-column-def
上記以外Workspace

選択ダイアログが開く場所

  • 入力欄が空なら、基準ディレクトリを開きます
  • 値が入っていれば、その場所を開きます。相対パスの場合は、基準ディレクトリ、Workspace、アプリの起動ディレクトリの順に探し、見つかった場所を開きます
  • 入力欄の横の開くボタンも、同じ方法で場所を決めてエクスプローラーで開きます

選択後に入る値

選んだ場所入力欄に入る値
基準ディレクトリの中基準ディレクトリからの相対パス（例：resources/setting/orders.json を選ぶと orders.json）
基準ディレクトリの外で、Workspace の中Workspace からの相対パス
Workspace の外絶対パス

実行時のパスの解決

オプションの種類相対パスの解決方法
入力データ（-src）Dataset Base、Workspace、起動ディレクトリの順に探す
出力先（-result）常に Result Base の下に出力する
設定・テンプレート・JDBC など（resources/ 系）基準ディレクトリ、Workspace の順に探す（GUI の Exec と Save Shell で作った .bat で同じ）

再利用のためのポイント

  • 相対パスで保存したオプションは、Workspace / Dataset Base / Result Base を切り替えると、切り替え先の同じ相対位置を指します。基本的な使い方 の「7. Dataset Base / Result Base / Env を使い分けて再利用する」はこの仕組みを使っています
  • Workspace の外を選ぶと絶対パスになり、切り替えても同じ場所を指したままになります。環境ごとに変えたいファイルは Workspace（入力データなら Dataset Base）の中に置いてください
  • 設定・テンプレート・JDBC などのファイルは、基準ディレクトリの中に置くと、ファイル名だけで指定できて管理しやすくなります

コマンド（Convert / Compare / Generate / Run / Parameterize）ごとに、Workspace の option/<command>/ に保存された保存済みオプションを一覧表示します。コマンド名をクリックすると一覧を開閉します。

操作動作Workspace への影響
名前保存済みオプションを読み込んでフォームに表示読み込みのみ
＋（Add）空の保存済みオプション new item を追加（同名があれば new item(1) のように連番）option/<command>/new item.txt を作成
⚙（設定）名前の横のボタン。次の操作メニューを開く—
Delete保存済みオプションを削除option/<command>/<name>.txt を削除

フッターの操作

保存済みオプションを選択しているときに画面下部に表示されます。

ボタン動作Workspace への影響
Edit Parameters (-P)SQL やテンプレートに渡す -P 値を入力（設定数が右に表示される）。詳細は Parameters (-P) を参照Exec に渡され、Save で一緒に保存される（保存後は .bat でも使われる）。保存済みオプションを開くと保存済みの値に置き換わる
Execフォームに表示中の内容でコマンドを実行。保存は不要。実行中は Abandoned で中断でき、完了後は Open Directory で出力先を開ける。必須の未入力・存在しないファイル・同時に指定できないオプション・不正な値（数値・真偽値として読めない値、文字コード・正規表現・選択肢にない値など）があると実行せずに Invalid Option と表示し、該当する入力欄の下にメッセージを赤字で出す（入力し直すと消える。折りたたんだ欄など画面に出ていない欄のメッセージはダイアログで知らせる）相対パスは Workspace / Dataset Base / Result Base を基準に解決し、${env.変数名} は Env ファイルの値に置き換わる。結果は Result Base 配下に出力
Saveフォームに表示中の内容を保存済みオプションに上書き保存option/<command>/<name>.txt を上書き
Save Shell保存済みオプションを CLI で実行する .bat を作成。未保存の変更は含まれないため、先に Save する.bat はアプリの起動ディレクトリに <command>_<name>.bat で作成（Workspace の中ではない）。現在の Workspace / Dataset Base / Result Base / Env が埋め込まれる

環境変数（Env）

コマンドの引数に ${env.変数名} と書くと、実行時に Env ファイルに定義した値に置き換わります。JDBC の接続先などを変数にしておき、Env ファイルを切り替えるだけで同じ保存済みオプションを複数の環境で使い回せます。

Env ファイルの例

# env/staging.properties
host=staging-db
port=5432
user=app

オプションでの使い方

-jdbc.url=jdbc:postgresql://${env.host}:${env.port}/app
-jdbc.user=${env.user}
  • ファイルは UTF-8 の properties 形式で記述します
  • Env ファイルに定義されていない変数を参照するとエラーになります
  • 置き換えの対象はコマンドの引数です。JDBC 設定ファイル（resources/jdbc）の中身は置き換わりません
  • 保存したシェル（.bat）にも Env の指定が出力されます
  • CLI から実行する場合は Java システムプロパティ -Dyo.dbunit.cli.env=env/staging.properties で指定します

Parameters (-P) との使い分け

Env は Workspace 全体に効き、オプションの値を置き換えます。SQL やテンプレートの中では使えません。保存済みオプション 1 つだけに効き、SQL やテンプレートの変数として使う値は -P 値で渡します。比較表と組み合わせ方は Parameters (-P) の「Env との使い分け」を参照してください。
