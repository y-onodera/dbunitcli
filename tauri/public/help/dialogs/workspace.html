Workspace

Workspace は、パラメータやリソースファイルを置く作業ディレクトリです。ヘッダーの ChangeWorkspace ボタンからダイアログを開いて切り替えます。このページでは、Workspace を選んでからコマンドを作り、保存し、再利用するまでの流れを説明します。

基本の流れ

1. Workspace を選ぶ

ヘッダーの ChangeWorkspace ボタンでダイアログを開き、Workspace を選んで confirm を押します。Dataset Base / Result Base / Env は空欄のままでもかまいません（それぞれ Workspace、Workspace、env.properties になります）。切り替えると、サイドバーのパラメータ一覧と各設定ダイアログの内容が、新しい Workspace のものに変わります。各項目の詳細は ChangeWorkspace の入力項目 を参照してください。

2. コマンドを選ぶ

サイドバーでコマンド名（Convert / Compare / Generate / Run / Parameterize）をクリックすると、保存済みパラメータの一覧が開きます。

  • 新しく作る場合は ＋ を押します。new item という名前のパラメータが作られます
  • 既存のものを使う場合はパラメータ名をクリックします。フォームに内容が表示され、ヘッダー右側に コマンド: パラメータ名 が表示されます
  • 既存のパラメータを元に別のものを作る場合は、⚙ の Copy で複製してから開きます

3. Exec で実行しながらオプションを決める

フォームでオプションを入力し、フッターの Exec を押して実行します。Exec はフォームに表示中の内容をそのまま実行するので、保存していなくても試せます。結果のダイアログにある Open Directory で出力先を開いて、出力を確認します。期待どおりになるまで、オプションを変えて Exec を繰り返してください。

  • 時間がかかる処理は、実行中に Abandoned を押すと中断できます
  • SQL やテンプレートに渡す値は Edit Parameters (-P) で入力できます。入力した値は Save でパラメータと一緒に保存されます（Parameters (-P) を参照）
  • 入力欄の横のファイル選択・ディレクトリ選択ボタンで選んだパスは、オプションごとの基準ディレクトリからの相対パスで入ります（ファイル選択と Workspace を参照）
  • あとで別の環境やデータで使い回す予定があるなら、この段階でパスを相対パスにし、接続先などを ${env.変数名} にしておきます（7. を参照）

4. Save で保存する

オプションが決まったら、フッターの Save を押します。フォームの内容と Edit Parameters (-P) の値が option/<command>/<name>.txt に上書き保存されます。名前は、サイドバーの ⚙ から rename で分かりやすいものに変えてください。

5. Save Shell で .bat を保存する

GUI を使わずに別のシェルやタスクスケジューラから実行したい場合は、フッターの Save Shell を押します。

  • .bat は保存済みのパラメータを実行します。フォームで変えたばかりの内容は入らないので、先に Save してください
  • .bat はアプリを起動したディレクトリに <command>_<name>.bat という名前で作られます（Workspace の中ではありません）。同じ名前のファイルがあると上書きされます
  • 作るときの Workspace / Dataset Base / Result Base / Env が .bat に書き込まれます

6. Parameterize で繰り返し処理する

同じコマンドを値だけ変えて何回も実行したい場合は、Parameterize を使います。

  1. 元にするパラメータを Save しておきます（Parameterize は保存済みの内容から作られます）
  2. サイドバーでそのパラメータの ⚙ を押し、Parameterize を選びます。次の 3 つが作られ、Parameterize のフォームが開きます
    • テンプレート option/parameterize/template/<name>.txt：各オプションが -オプション名=$param.オプション名$ の形になります
    • パラメータ値の CSV <workspace>/<name>.csv：今の値が 1 行だけ入っています
    • Parameterize のパラメータ option/parameterize/<name>.txt
  3. CSV に、実行したい回数ぶん行を足して値を変えます。変えない列はテンプレートで固定の値に書き換えてもかまいません
  4. Exec で実行すると、CSV の行ごとにコマンドが実行されます。確認できたら Save し、必要なら Save Shell で .bat にします

unit や cmdParam などの設定は Parameterize を参照してください。

7. Dataset Base / Result Base / Env を使い分けて再利用する

パラメータの中ではパスを相対パスで書き、環境で変わる値を ${env.変数名} にしておくと、パラメータを書き換えずに ChangeWorkspace の設定だけで使い回せます。

切り替えるもの向いている場面パラメータの書き方
Dataset Base入力データだけが違う（例：月ごとのデータフォルダ、テスト用と本番用の入力）入力ファイル（src など）を相対パスで書く
Result Base出力先を分けたい（例：環境ごと、実行日ごと）出力先（result など）を相対パスで書く
Env接続先・ユーザー・スキーマなどの値が環境ごとに違う（例：開発 DB とステージング DB）値を ${env.変数名} で書き、環境ごとの .properties を用意する
Workspaceパラメータやリソース一式を別にしたい（例：プロジェクトごと）—（パラメータ・設定ファイルごと切り替わる）

例：開発環境で作ったパラメータをステージングで使う場合

  1. 開発環境用の env/dev.properties とステージング用の env/staging.properties を用意する
  2. パラメータの接続先を ${env.host} などにして Save する
  3. ChangeWorkspace で Env を env/staging.properties、Result Base をステージング用の出力先に変えて confirm
  4. 同じパラメータをそのまま Exec する。.bat も環境ごとに作る場合は、Save Shell のあとで .bat の名前を変えておく（同じ名前だと上書きされるため）

ChangeWorkspace の入力項目

項目説明デフォルト
Workspace作業ディレクトリ（必須）。存在しない場合は作成されます。%USERPROFILE% / %HOME% を使えます起動ディレクトリ
Dataset Baseデータセット（入力ファイル）を相対パスで指定したときの基準ディレクトリWorkspace
Result Base出力先を相対パスで指定したときの基準ディレクトリWorkspace
Env環境変数ファイル（.properties）のパス。Workspace からの相対パスで指定します（絶対パスも可）。ファイル選択で Workspace 配下を選ぶと相対パスに変換されます。空欄にするとデフォルトに戻りますenv.properties

Workspace を変更すると、Workspace で始まる Dataset Base / Result Base は新しい Workspace に合わせて書き換わります。

Workspace のディレクトリ構成

<workspace>/
├── env.properties             環境変数ファイル（デフォルト）
├── option/
│   ├── <command>/             コマンドごとの保存済みパラメータ
│   └── parameterize/template/ Parameterize 用テンプレート
└── resources/
    ├── setting/               Dataset Settings
    ├── template/              テンプレート
    ├── jdbc/                  JDBC 接続設定
    ├── xlsxSchema/            Xlsx Schema
    └── fixed-column-def/      固定長カラム定義

各入力欄でファイル名だけ指定した場合は、対応するディレクトリ、Workspace の順に探します。

Workspace の影響範囲

Workspace を切り替えると、次の画面要素が新しい Workspace の内容に切り替わります。どのボタンがどこを読み書きするかは サイドバー と フッター を参照してください。

画面要素読み書きする場所
サイドバーoption/<command>/*.txt（パラメータ一覧）
フォームの各設定ダイアログresources/ 配下（Dataset Settings・テンプレート・JDBC・Xlsx Schema・固定長カラム定義）
フォームの相対パス入力ファイルは Dataset Base、出力先は Result Base、それ以外は Workspace を基準に解決
Exec / Save ShellEnv ファイル（${env.変数名} の置き換え）

ファイル選択と Workspace

フォームでオプションを組み立てるとき、入力欄の横のファイル選択・ディレクトリ選択ボタンは、オプションごとに決まった基準ディレクトリを使います。基準ディレクトリは ChangeWorkspace の設定で決まるので、Workspace / Dataset Base / Result Base を切り替えると、選択ダイアログの開く場所と相対パスの意味も変わります。

オプションごとの基準ディレクトリ

オプション基準ディレクトリ
-src（入力データ）Dataset Base
-result（出力先）Result Base
-setting / -unitSetting<workspace>/resources/setting
-template（Generate）/ -templateGroup<workspace>/resources/template
-template（Parameterize）<workspace>/option/parameterize/template
-jdbcProperties<workspace>/resources/jdbc
-xlsxSchema<workspace>/resources/xlsxSchema
-fixedColumnDef<workspace>/resources/fixed-column-def
上記以外Workspace

選択ダイアログが開く場所

  • 入力欄が空なら、基準ディレクトリを開きます
  • 値が入っていれば、その場所を開きます。相対パスの場合は、基準ディレクトリ、Workspace、アプリの起動ディレクトリの順に探し、見つかった場所を開きます
  • 入力欄の横の開くボタンも、同じ方法で場所を決めてエクスプローラーで開きます

選択後に入る値

選んだ場所入力欄に入る値
基準ディレクトリの中基準ディレクトリからの相対パス（例：resources/setting/orders.json を選ぶと orders.json）
基準ディレクトリの外で、Workspace の中Workspace からの相対パス
Workspace の外絶対パス

実行時のパスの解決

オプションの種類相対パスの解決方法
入力データ（-src）Dataset Base、Workspace、起動ディレクトリの順に探す
出力先（-result）常に Result Base の下に出力する
設定・テンプレート・JDBC など（resources/ 系）基準ディレクトリ、Workspace の順に探す（GUI の Exec と Save Shell で作った .bat で同じ）

再利用のためのポイント

  • 相対パスで保存したオプションは、Workspace / Dataset Base / Result Base を切り替えると、切り替え先の同じ相対位置を指します。7. の使い分けはこの仕組みを使っています
  • Workspace の外を選ぶと絶対パスになり、切り替えても同じ場所を指したままになります。環境ごとに変えたいファイルは Workspace（入力データなら Dataset Base）の中に置いてください
  • 設定・テンプレート・JDBC などのファイルは、基準ディレクトリの中に置くと、ファイル名だけで指定できて管理しやすくなります

環境変数（Env）

コマンドの引数に ${env.変数名} と書くと、実行時に Env ファイルに定義した値に置き換わります。JDBC の接続先などを変数にしておき、Env ファイルを切り替えるだけで同じパラメータを複数の環境で使い回せます。

Env ファイルの例

# env/staging.properties
host=staging-db
port=5432
user=app

パラメータでの使い方

-jdbc.url=jdbc:postgresql://${env.host}:${env.port}/app
-jdbc.user=${env.user}
  • ファイルは UTF-8 の properties 形式で記述します
  • Env ファイルに定義されていない変数を参照するとエラーになります
  • 置き換えの対象はコマンドの引数です。JDBC 設定ファイル（resources/jdbc）の中身は置き換わりません
  • 保存したシェル（.bat）にも Env の指定が出力されます
  • CLI から実行する場合は Java システムプロパティ -Dyo.dbunit.cli.env=env/staging.properties で指定します

Parameters (-P) との使い分け

Env は Workspace 全体に効き、オプションの値を置き換えます。SQL やテンプレートの中では使えません。パラメータ 1 ファイルだけに効き、SQL やテンプレートの変数として使う値は Parameters (-P) で渡します。比較表と組み合わせ方は Parameters (-P) の「Env との使い分け」を参照してください。
