Workspace

パラメータやリソースファイルを置く作業ディレクトリを切り替えます。ヘッダーの ChangeWorkspace ボタンからダイアログを開き、confirm で反映します。

入力項目

項目説明デフォルト
Workspace作業ディレクトリ（必須）。存在しない場合は作成されます。%USERPROFILE% / %HOME% を使えます起動ディレクトリ
Dataset Baseデータセット（入力ファイル）を相対パスで指定したときの基準ディレクトリWorkspace
Result Base出力先を相対パスで指定したときの基準ディレクトリWorkspace
Env環境変数ファイル（.properties）のパス。Workspace からの相対パスで指定します（絶対パスも可）。ファイル選択で Workspace 配下を選ぶと相対パスに変換されます。空欄にするとデフォルトに戻りますenv.properties

Workspace を変更すると、Workspace で始まる Dataset Base / Result Base は新しい Workspace に合わせて書き換わります。

Workspace のディレクトリ構成

<workspace>/
├── env.properties             環境変数ファイル（デフォルト）
├── option/
│   ├── <command>/             コマンドごとの保存済みパラメータ
│   └── parameterize/template/ Parameterize 用テンプレート
└── resources/
    ├── setting/               Dataset Settings
    ├── template/              テンプレート
    ├── jdbc/                  JDBC 接続設定
    ├── xlsxSchema/            Xlsx Schema
    └── fixed-column-def/      固定長カラム定義

各入力欄でファイル名だけ指定した場合は、対応するディレクトリ、Workspace の順に探します。

Workspace の影響範囲

Workspace を切り替えると、次の画面要素が新しい Workspace の内容に切り替わります。どのボタンがどこを読み書きするかは サイドバー と フッター を参照してください。

画面要素読み書きする場所
サイドバーoption/<command>/*.txt（パラメータ一覧）
フォームの各設定ダイアログresources/ 配下（Dataset Settings・テンプレート・JDBC・Xlsx Schema・固定長カラム定義）
フォームの相対パス入力ファイルは Dataset Base、出力先は Result Base、それ以外は Workspace を基準に解決
Exec / Save ShellEnv ファイル（${env.変数名} の置き換え）

サイドバーの使い方

コマンド（Convert / Compare / Generate / Run / Parameterize）ごとに、Workspace の option/<command>/ に保存されたパラメータを一覧表示します。コマンド名をクリックすると一覧を開閉します。

操作動作Workspace への影響
パラメータ名パラメータを読み込んでフォームに表示読み込みのみ
＋（Add）空のパラメータ new item を追加（同名があれば new item(1) のように連番）option/<command>/new item.txt を作成
⚙（設定）パラメータ名の横のボタン。次の操作メニューを開く—
Deleteパラメータを削除option/<command>/<name>.txt を削除
rename入力欄に新しい名前を入れて確定ボタンで変更（同名があれば連番）ファイル名を変更
Copyパラメータを複製（<name>(1) のように連番）複製したファイルを作成
Parameterizeパラメータから Parameterize 用のパラメータを作成して開く（Parameterize 以外のコマンドのみ）option/parameterize/template/<name>.txt（テンプレート）、Workspace 直下の <name>.csv（パラメータ値）、option/parameterize/<name>.txt を作成
Helpサイドバー下部のボタン。各コマンドのヘルプを開く—

フッターの使い方

パラメータを選択しているときに画面下部に表示されます。

ボタン動作Workspace への影響
Edit Parameters (-P)テンプレートなどに渡す -P パラメータを入力（設定数が右に表示されます）Exec / Save の内容に含まれる
Execフォームに表示中の内容でコマンドを実行。保存は不要です。実行中は Abandoned で中断でき、完了後は Open Directory で出力先を開けます相対パスは Workspace / Dataset Base / Result Base を基準に解決し、${env.変数名} は Env ファイルの値に置き換わる。結果は Result Base 配下に出力
Saveフォームに表示中の内容をパラメータに上書き保存option/<command>/<name>.txt を上書き
Save Shell保存済みのパラメータを CLI で実行する .bat を作成。未保存の変更は含まれないため、先に Save してください.bat はアプリの起動ディレクトリに <command>_<name>.bat で作成（Workspace の中ではない）。現在の Workspace / Dataset Base / Result Base / Env が埋め込まれる

使い方の流れ

  1. ヘッダーの ChangeWorkspace で Workspace を選び、必要なら Dataset Base / Result Base / Env を指定して confirm
  2. サイドバーでコマンドを開き、＋ で新しいパラメータを作るか、既存のパラメータ名をクリックして開く
  3. フォームを入力し、Exec で実行して結果を確認
  4. Save でパラメータを保存（必要ならサイドバーの ⚙ から rename）
  5. 同じパラメータを別の環境で使うときは、ChangeWorkspace で Env だけを切り替えて Exec
  6. CLI で繰り返し実行するときは Save Shell で .bat を作成

環境変数（Env）

コマンドの引数に ${env.変数名} と書くと、実行時に Env ファイルに定義した値に置き換わります。JDBC の接続先などを変数にしておき、Env ファイルを切り替えるだけで同じパラメータを複数の環境で使い回せます。

Env ファイルの例

# env/staging.properties
host=staging-db
port=5432
user=app

パラメータでの使い方

-jdbc.url=jdbc:postgresql://${env.host}:${env.port}/app
-jdbc.user=${env.user}
  • ファイルは UTF-8 の properties 形式で記述します
  • Env ファイルに定義されていない変数を参照するとエラーになります
  • 置き換えの対象はコマンドの引数です。JDBC 設定ファイル（resources/jdbc）の中身は置き換わりません
  • 保存したシェル（.bat）にも Env の指定が出力されます
  • CLI から実行する場合は Java システムプロパティ -Dyo.dbunit.cli.env=env/staging.properties で指定します
