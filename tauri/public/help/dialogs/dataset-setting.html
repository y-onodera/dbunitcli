Dataset Setting

個別テーブルに対するメタデータ設定を編集するダイアログです。対象指定、分割・リネーム、派生テーブルの分離、追加カラム、フィルタ／並び順を構成します。ファイル全体の構造（settings / commonSettings / import）については Dataset Settings を参照してください。

シンプルな使い方

Target で対象のテーブルを選び、Columns / Order や Filter などで適用する内容を指定します。Dataset Settings の表の行の edit（新しく作るときは表の add）で開きます。

例: users から更新日時のカラムを外し、id を主キーにします。

入力 (users):
  id | name  | updated_at
  1  | Alice | 2024-01-02 09:00:00

指定:
  Target の name       = users
  Columns / Order の keys    = id
  Columns / Order の exclude = updated_at
  → Save

結果 (users):
  id | name
  1  | Alice   （主キーは id）
  • Save を押すと Dataset Settings の表に反映される。ファイルに書き出すのは Dataset Settings の Save
  • Preview で、保存する前にこの設定を適用した結果を確認できる
  • 行を絞り込む filter は JEXL 式で書く（下記「JEXL 式の書き方」）

Target

処理対象のテーブルをどのように特定するかを選択します。

項目説明
nameテーブル名を1件以上列挙して指定する（完全一致）。filePath（正規表現）を指定すると、読み込み元ファイルの絶対パス（区切り文字は /）全体がこれに一致するファイル由来のテーブルだけが対象になる（例: .*/master/.*）。
patternテーブル名のマッチで対象を特定する。string はテーブル名の部分一致（* はすべてのテーブルに一致）、regex はテーブル名全体に一致する正規表現（両方あれば regex を使う）。exclude に除外するテーブル名（完全一致）を指定できる。filePath（正規表現）を指定すると、そのパスに一致するファイル由来のテーブルのみが対象になる。
outerJoin / innerJoin / fullJoin2テーブルを結合して1つの論理テーブルとして扱う。left と right に結合対象のテーブル名、条件は on（JEXL 式）か column（共通カラム名）で指定する。filePath（正規表現）を指定すると、left / right ともそのパスに一致するファイル由来のテーブルのみを結合対象にする。right だけ別のパスにしたい場合は rightFilePath を指定する（指定した場合 right は filePath より優先される）。

変化の例

name（対象テーブルの絞り込み）

入力に users、orders、logs がある状態で name: ["users", "orders"] を指定すると、logs は処理対象から外れます。

pattern（部分一致・正規表現）

pattern: { string: "t_", exclude: ["t_tmp"] } を指定すると、t_users や t_orders は対象になり、t_tmp は除外されます。exclude は完全一致のため、t_tmp_work は除外されません。

pattern: { regex: "t_(users|orders)" } を指定すると、テーブル名全体が一致する t_users と t_orders だけが対象になります。

innerJoin（内部結合）

Before (orders):
order_id | item_id | qty
---------+---------+----
1        | 101     | 2
2        | 102     | 3
3        | 999     | 1

Before (items):
id  | name
----+------
101 | Pen
102 | Book

After innerJoin (left=orders, right=items, column=["item_id","id"]):
orders_order_id | orders_item_id | orders_qty | items_id | items_name
----------------+----------------+------------+----------+-----------
1               | 101            | 2          | 101      | Pen
2               | 102            | 3          | 102      | Book

outerJoin は左側（orders）の全行を残し、一致しない右側カラムは NULL になります。fullJoin は両側の未一致行も残します。

Split / Rename

split を有効にすると、1つの入力から複数テーブルを派生させることができます。無効時はリネーム設定として機能します。

項目説明
prefix出力テーブル名に付与する接頭辞
tableName出力テーブル名のベース名
suffix出力テーブル名に付与する接尾辞
limit1 出力テーブルあたりに含める breakKey のグループ数（breakKey 未指定時は行数）の上限。上限に達すると次の行から新しい出力テーブルへ切り替わる。0（未指定）のとき split は行われない。
breakKeysplit 時にテーブルを切り替えるキーとなるカラム。値が変化した回数が limit に達すると出力テーブルが切り替わる。未指定の場合は limit 行ごとに切り替わる。

変化の例

prefix / tableName / suffix（リネーム）

入力 users に対し prefix: "tmp_"、tableName: "accounts"、suffix: "_v1" を指定すると、出力テーブル名は tmp_accounts_v1 になります。データ内容はそのまま維持されます。

split（breakKey でグループ単位に分割）

出力テーブル名は prefix / suffix に %d を含めることで、分割順の連番（0, 1, 2, ...）が埋め込まれます。breakKey の値自体はテーブル名には使われません。

Before (orders, breakKey 昇順にソート済み):
id | type | amount
---+------+-------
1  | A    | 100
3  | A    | 150
2  | B    | 200
4  | C    | 80

After (split: { tableName: "orders", suffix: "_%d", breakKey: ["type"], limit: 1 }):
Table: orders_0
id | type | amount
---+------+-------
1  | A    | 100
3  | A    | 150

Table: orders_1
id | type | amount
---+------+-------
2  | B    | 200

Table: orders_2
id | type | amount
---+------+-------
4  | C    | 80

split.limit（1 テーブルに含めるグループ数の上限）

limit は「1 出力テーブルあたりに含める breakKey のグループ数の上限」です。上限に達すると、それ以降の行は新しい出力テーブルに振り分けられます（行は破棄されません）。上記と同じ入力に対して limit: 2 を指定すると、2 グループ分（A と B）が 1 テーブル目に、残りのグループ（C）が 2 テーブル目に格納されます。

After (split: { tableName: "orders", suffix: "_%d", breakKey: ["type"], limit: 2 }):
Table: orders_0
id | type | amount
---+------+-------
1  | A    | 100
3  | A    | 150
2  | B    | 200

Table: orders_1
id | type | amount
---+------+-------
4  | C    | 80

breakKey を指定しない場合、limit は「1 出力テーブルあたりの行数」として扱われ、limit 行ごとに新しい出力テーブルへ切り替わります。

Separate

separate は配列で、各要素が 1 つの派生テーブル定義となり、1 つの入力から複数の派生テーブルを並列に生成します。split が breakKey / limit で連番テーブルを自動生成するのに対し、separate は派生テーブルごとに列・行・並び順などを明示的に自由定義できる点が異なります。

各派生テーブルでは、通常のテーブル設定と同じフィールドを指定できます。include / exclude による列方向の切り出しと、filter / distinct による行方向の切り出しの両方に利用でき、1 要素の中で同時に指定することも可能です。

項目説明
name派生テーブルの出力テーブル名
keys派生テーブルの主キーとなるカラム
include派生テーブルに残すカラム（列の切り出し）。指定すると include 以外は除外される。
exclude派生テーブルから除外するカラム
filter派生テーブルに残す行の条件（JEXL 式）。複数指定した場合は AND 扱い。
order派生テーブル内の並び順に使用するカラム
distinct派生テーブルの重複行を排除するフラグ
string / number / boolean / sqlFunction追加カラム定義。派生テーブルごとに個別に指定できる（詳細は Additional Columns を参照）。

変化の例

列方向の切り出し（連絡先カラムを別テーブルへ）

入力 users から連絡先関連のカラムだけを user_profiles に切り出します。元テーブル users 自体は separate の対象外になるため、連絡先カラムを残したい場合は別途 settings を追加してください。

Before (users):
user_id | name  | address       | tel          | fax
--------+-------+---------------+--------------+--------------
1       | Alice | Tokyo         | 03-0000-0001 | 03-0000-0002
2       | Bob   | Osaka         | 06-0000-0001 | 06-0000-0002

After (separate: [{ name: "user_profiles", keys: ["user_id"], include: ["user_id", "address", "tel", "fax"] }]):
Table: user_profiles
user_id | address | tel          | fax
--------+---------+--------------+--------------
1       | Tokyo   | 03-0000-0001 | 03-0000-0002
2       | Osaka   | 06-0000-0001 | 06-0000-0002

行方向の切り出し（ステータス別に派生テーブルを作成）

separate 配列に複数要素を定義することで、同じ入力から異なる条件の派生テーブルを並列に生成できます。

Before (orders):
id | status   | amount
---+----------+-------
1  | APPROVED | 1500
2  | REJECTED | 500
3  | APPROVED | 2000
4  | REJECTED | 300

After (separate: [
  { name: "orders_approved", keys: ["id"], filter: ["status == 'APPROVED'"] },
  { name: "orders_rejected", keys: ["id"], filter: ["status == 'REJECTED'"] }
]):
Table: orders_approved
id | status   | amount
---+----------+-------
1  | APPROVED | 1500
3  | APPROVED | 2000

Table: orders_rejected
id | status   | amount
---+----------+-------
2  | REJECTED | 500
4  | REJECTED | 300

列方向 + 行方向の組み合わせ

1 つの派生テーブル定義の中で include と filter を同時に指定すると、「条件に合致する行」の「特定カラムだけ」を切り出せます。

Before (orders):
id | status   | amount | memo
---+----------+--------+------
1  | APPROVED | 1500   | x
2  | REJECTED | 500    | y
3  | APPROVED | 2000   | z

After (separate: [{ name: "orders_approved_summary", keys: ["id"], include: ["id", "amount"], filter: ["status == 'APPROVED'"] }]):
Table: orders_approved_summary
id | amount
---+-------
1  | 1500
3  | 2000

Additional Columns

元データに存在しないカラムを追加します。値には JEXL 式を記述できます。

型説明
string文字列型カラム。既存カラムの連結や substring による抽出に利用する。
number数値型カラム。算術演算で集計値や派生値を定義する。
boolean真偽値型カラム。条件式で判定結果を持たせる。
sqlFunction関数表現によるカラム。複雑なロジックを JEXL 関数として定義する。

行の追加・削除・確定の動きは 画面共通の操作 の「ダイアログの複数値の入力欄」を参照してください。

読み込んだカラムの反映

展開すると先頭に Load Columns ボタンが表示されます。使い方は Columns / Order・Filter の「Load Columns」と同じで、取得したカラムはどの組でも共通です。取得したカラムは get('カラム名') の形で式に反映します。日本語や記号を含むカラム名もそのまま参照できます。

反映するときに、カラムを関数で囲むかを function で選べます。

function反映される式
noneget('カラム名')
tryToNumtryToNum(get('カラム名'), default)。default が空なら null になる。
formatDateformatDate(get('カラム名'), 'from', 'to', default)。default が空なら 3 引数の形になる。
contains / startsWith / endsWith / matchesget('カラム名').contains('argument') など。argument は文字列として埋め込む（matches では正規表現）。
substringget('カラム名').substring(start, end)。end が空なら substring(start) になる。

default には JEXL 式をそのまま書きます（文字列なら '' のようにシングルクォートで囲みます）。初期値は number では 0、それ以外では '' です。from / to / argument はシングルクォートを付けずに値だけを書きます。start / end は数値（JEXL 式）を書きます。関数・メソッドの詳しい動きは「JEXL 式の書き方」を参照してください。

  • select: 各型の add の右に表示されます。Select Columns ダイアログでカラムを複数選んで Apply を押すと、カラム名を name、カラムを参照する式を値とした行をまとめて末尾に追加します。その型に同じ name の行が既にあるカラムは追加しません。Load Columns でカラムを取得するまでは表示されません。
  • edit: 各行の右に表示され、値の式をテキストエリアで編集するダイアログを開きます。Apply で行の値に反映します。
    • operator で演算子を選び Insert Operator を押すと、テキストエリアのカーソル位置に演算子を挿入します。選べる演算子は「JEXL 式の書き方」の「演算子」の表と同じ。二項演算子は前後に空白を付けて挿入する
    • column でカラムを選び Insert Column を押すと、カーソル位置にカラムを参照する式を挿入します。function の指定は上の表と同じ。カラムを取得していない場合は表示されない
    • 文字列を選択した状態で挿入すると、選択した部分を置き換えます。挿入後のカーソルは挿入した文字列の直後に移るため、続けて挿入すると後ろに並ぶ

変化の例

string（文字列連結）

Before (users):
id | firstName | lastName
---+-----------+---------
1  | John      | Smith
2  | Anna      | Lee

After (string: { fullName: "firstName + ' ' + lastName" }):
id | firstName | lastName | fullName
---+-----------+----------+-----------
1  | John      | Smith    | John Smith
2  | Anna      | Lee      | Anna Lee

number（算術による派生カラム）

Before (items):
id | price | quantity
---+-------+---------
1  | 100   | 3
2  | 250   | 2

After (number: { subtotal: "price * quantity" }):
id | price | quantity | subtotal
---+-------+----------+---------
1  | 100   | 3        | 300
2  | 250   | 2        | 500

boolean（条件式による判定）

Before (users):
id | age
---+----
1  | 25
2  | 17

After (boolean: { adult: "age >= 20" }):
id | age | adult
---+-----+------
1  | 25  | true
2  | 17  | false

sqlFunction（条件分岐による区分値）

Before (orders):
id | status
---+---------
1  | APPROVED
2  | REJECTED
3  | PENDING

After (sqlFunction: { mark: "status == 'APPROVED' ? 'OK' : (status == 'REJECTED' ? 'NG' : 'HOLD')" }):
id | status   | mark
---+----------+-----
1  | APPROVED | OK
2  | REJECTED | NG
3  | PENDING  | HOLD

Columns / Order・Filter

exclude / include / keys / order は Columns / Order の組に、JEXL 式で書く filter は Filter の組に表示されます。

項目説明
exclude処理から除外するカラム
include処理対象にするカラム（指定すると include 以外は除外）
keys主キーのカラム名
filterデータ選択条件（JEXL 式）。複数指定した場合は AND 扱い。
order並び順に使用するカラム

各項目には同じ値を重複して設定できません。行の追加・削除・確定と重複したときの動きは 画面共通の操作 の「ダイアログの複数値の入力欄」を参照してください。

Load Columns

Columns / Order と Filter の先頭にある Load Columns ボタンで、各フィールドのカラム名入力の候補（入力補助）を読み込めます。どの組の Load Columns ボタンも同じ動きで（Additional Columns を含む）、取得したカラムはすべての組で使えます。

  1. Load Columns を押すと、Target の指定に該当するテーブルの一覧が表示されます。Target でテーブル名やパターンを指定していない場合は、データセット内のすべてのテーブルが表示されます。
  2. 候補にしたいテーブルの行で Load Columns を押すと、そのテーブルのカラム名が取得されます。読み込むのは選んだテーブルだけです。
  3. カラム名の取得に失敗したときは、一覧を閉じずにエラーメッセージと読込中に出ていたログを表示します。別のテーブルを選び直せます。
  4. 取得後は exclude / include / keys / filter / order の入力欄でカラム名が候補として表示されます。

入力欄の候補表示だけでは、フィールドの値自体は変更されません。値を設定したい場合は、次の「カラムの一括選択」を使います。

カラムの一括選択

Load Columns でカラム名を取得すると、exclude / include / keys / filter / order の各入力欄の右に select が表示されます。取得したカラムの中から複数を一度に選んで設定できます。

  1. 設定したい項目の行で select を押すと、取得済みカラムをチェックボックスで選べる Select Columns ダイアログが開きます。
  2. 設定するカラムにチェックを入れて Apply を押します。1件も選択していない間は Apply は押せません。
  3. 選択したカラムのうち、その項目の他の行に既にあるものは除かれます。残りの先頭の1件は select を押した行に設定され（元の値は上書きされます）、それ以外は末尾に追加されます。すべて他の行にある場合は何も変わりません。

Load Columns でカラムを取得するまでは、select は表示されません。

filter では、カラム名ではなくカラムを参照する式（get('カラム名')）を設定します。Select Columns ダイアログで function も選べます（指定の仕方は Additional Columns の「読み込んだカラムの反映」と同じ。例: startsWith を選ぶと get('区分').startsWith('SALE')）。複数選んだ場合の行への入り方は上と同じで、filter の行は AND で組み合わさります。

filter の式の編集

filter の各行の右にある edit で、式をテキストエリアで編集するダイアログを開きます。値が空の行でも使えます。演算子・カラムの挿入の仕方は Additional Columns の edit ボタンと同じです。Apply で行に反映します。他の行と同じ式になる場合は反映されません。

変化の例

exclude（カラム除外）

Before (users):
id | name  | created_at          | updated_at
---+-------+---------------------+---------------------
1  | Alice | 2024-01-01 10:00:00 | 2024-01-02 09:00:00

After (exclude: ["created_at", "updated_at"]):
id | name
---+------
1  | Alice

include（対象カラムの限定）

Before (users):
id | name  | email       | age
---+-------+-------------+----
1  | Alice | a@example   | 25

After (include: ["id", "name"]):
id | name
---+------
1  | Alice

keys（主キー指定）

カラム構成や行数は変わりません。比較コマンドでの突合キーや、distinct・ソート挙動の基準として使われます。

filter（行のフィルタ）

Before (orders):
id | amount | status
---+--------+---------
1  | 1500   | APPROVED
2  | 500    | APPROVED
3  | 2000   | REJECTED

After (filter: ["amount > 1000 && status == 'APPROVED'"]):
id | amount | status
---+--------+---------
1  | 1500   | APPROVED

order（並び替え）

Before (users):
id | name
---+------
3  | Carol
1  | Alice
2  | Bob

After (order: ["id"]):
id | name
---+------
1  | Alice
2  | Bob
3  | Carol

JEXL 式の書き方

filter、追加カラム（string / number / boolean / sqlFunction）、結合条件 on では Apache Commons JEXL3 の式を利用できます。

演算子

カテゴリ演算子
比較==, !=, >, <, >=, <=
正規表現=~（値全体が正規表現に一致する）, !~（一致しない）。例: type =~ 'SALE.*'
論理&& (AND), || (OR), ! (NOT)
算術+, -, *, /, %
文字列連結+
三項condition ? valueIfTrue : valueIfFalse
NULL 比較== null, != null

文字列メソッド

  • contains(str) — 指定文字列を含むか
  • startsWith(prefix) — 指定文字列で始まるか
  • endsWith(suffix) — 指定文字列で終わるか
  • matches(regex) — 正規表現にマッチするか
  • substring(start, end) — 部分文字列の取得

文字列リテラルはシングルクォートで囲みます（例: 'APPROVED'）。

日本語や記号を含むカラム名はそのままでは式に書けないため、get('カラム名') で参照します（例: get('金額(円)') > 1000）。

関数

次の関数は、Excel テンプレート（Jxls）の ${...} の中でも使えます。

関数説明
tryToNum(value, default)value を数値に変換できればその数値、できなければ default を返す。value が NULL の場合も default を返す。桁区切りの , を含む値（例: '1,234.5'）も数値に変換する。number で使う場合は、default に数値を指定してください。
formatDate(value, from, to)value を書式 from の日付として読み、書式 to の文字列にして返す。読めない場合（書式違い・2/30 のような存在しない日付・空文字）は value をそのまま返す。value が NULL の場合は NULL を返す。
formatDate(value, from, to, default)読めない場合と value が NULL の場合に default を返す。それ以外は 3 引数と同じ

from / to の書式は yyyy（年）、MM（月）、dd（日）、HH（時）、mm（分）、ss（秒）、E（曜日）などの組み合わせで書きます。M / d のように 1 文字にすると、2026/1/6 のような桁がそろっていない値も読めます。to に from にない項目（日付だけの値に HH など）を書くとエラーになります。

記述例

filter（金額とステータスの複合条件）

amount > 1000 && status == 'APPROVED'

filter（NULL 判定と前方一致）

type != null && type.startsWith('SALE')

boolean（カラム名の接尾辞で判定）

col.endsWith('_amount')

string（フルネーム連結）

firstName + ' ' + lastName

string（日付の年月日部分を抽出）

created_at.substring(0, 10)

string（日付の書式を変える。読めない値は空にする）

formatDate(order_date, 'yyyyMMdd', 'yyyy/MM/dd', '')

number（小計の算出）

price * quantity

number（数値にできない値を 0 にする）

tryToNum(amount, 0)

filter（数値として比較し、数値にできない行は除く）

tryToNum(amount, -1) > 1000

boolean（三項演算子による区分判定）

age >= 20 ? true : false

sqlFunction（条件に応じた区分値の生成）

status == 'APPROVED' ? 'OK' : (status == 'REJECTED' ? 'NG' : 'PENDING')

join.on（結合条件）

orders_item_id == items_id

結合時のカラム参照は <テーブル名>_<カラム名> の形式を使用します。

注意

  1. 文字列比較は大文字・小文字を区別します
  2. 日付比較は文字列として行われます（必要ならフォーマットを揃えてから比較）
  3. NULL との比較は必ず == null / != null を使用
  4. 複雑な条件は filter を複数行に分割して AND 合成することを推奨

Preview

ダイアログ下部の Preview を押すと、編集中のこの設定を適用した結果のテーブルの一覧を表示します（Dataset Load Form の Preview Apply Settings と同じ表示です）。一覧の preview ボタンを押すと、そのテーブルのデータを表示します。

  • 表示するのは Target（name / pattern / join）に該当するテーブルから作られたテーブルだけです。該当しないテーブルは表示しません。
  • テーブル名は設定を適用した後の名前で表示します（Split / Rename・Separate で変えた名前、join した結果の名前）。join の元になったテーブルは表示しません。
  • 適用するのはこのダイアログで編集中の設定 1 件だけです。同じファイルのほかの settings・commonSettings・outputFilter・import や、フォームの setting に指定したファイルは適用しません。
  • Save を押す前の内容でも確認でき、プレビューしても設定ファイルは保存されません。
  • Preview はフォームで srcType を指定しているときだけ表示されます。
