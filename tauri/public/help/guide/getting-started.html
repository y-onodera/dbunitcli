基本的な使い方

Workspace を選んでからコマンドを作り、実行・保存し、別の環境で使い回すまでの流れを説明します。各画面の項目の詳しい説明は、それぞれのリンク先を参照してください。

目次

  1. Workspace を選ぶ
  2. コマンドを選ぶ
  3. Exec で実行しながらオプションを決める
  4. Save で保存する
  5. Save Shell で .bat を保存する
  6. Parameterize で繰り返し実行する
  7. Dataset Base / Result Base / Env を使い分けて再利用する

1. Workspace を選ぶ

Workspace は、保存済みオプションや設定ファイルを置く作業ディレクトリです。ヘッダの ChangeWorkspace ボタンでダイアログを開き、Workspace を選んで confirm を押します。Dataset Base / Result Base / Env は空欄のままでもかまいません（それぞれ Workspace、Workspace、env.properties になります）。

切り替えると、サイドバーの保存済みオプションの一覧と各設定ダイアログの内容が、新しい Workspace のものに変わります。入力項目とディレクトリ構成は Workspace を参照してください。

2. コマンドを選ぶ

サイドバーでコマンド名（Convert / Compare / Generate / Run / Parameterize）をクリックすると、保存済みオプションの一覧が開きます。

  • 新しく作る場合は ＋ を押します。new item という名前の保存済みオプションが作られます
  • 既存のものを使う場合は名前をクリックします。フォームに内容が表示され、ヘッダ右側に コマンド: 名前 が表示されます
  • 既存のものを元に別のものを作る場合は、⚙ の Copy で複製してから開きます

各コマンドでできることは、ヘルプ一覧の「コマンド」から各ページを参照してください。

3. Exec で実行しながらオプションを決める

フォームでオプションを入力し、フッターの Exec を押して実行します。Exec はフォームに表示中の内容をそのまま実行するので、保存していなくても試せます。結果のダイアログにある Open Directory で出力先を開いて、出力を確認します。期待どおりになるまで、オプションを変えて Exec を繰り返してください。

  • 時間がかかる処理は、実行中に Abandoned を押すと中断できます
  • SQL やテンプレートに渡す値は Edit Parameters (-P) で入力できます。入力した -P 値は Save で一緒に保存されます（Parameters (-P) を参照）
  • 入力欄の横のファイル選択・ディレクトリ選択ボタンで選んだパスは、オプションごとの基準ディレクトリからの相対パスで入ります（Workspace の「ファイル選択と Workspace」を参照）
  • あとで別の環境やデータで使い回す予定があるなら、この段階でパスを相対パスにし、接続先などを ${env.変数名} にしておきます（7. を参照）

4. Save で保存する

オプションが決まったら、フッターの Save を押します。フォームの内容と -P 値が option/<command>/<name>.txt に上書き保存されます。名前は、サイドバーの ⚙ から rename で分かりやすいものに変えてください。

5. Save Shell で .bat を保存する

GUI を使わずに別のシェルやタスクスケジューラから実行したい場合は、フッターの Save Shell を押します。

  • .bat は保存済みの内容を実行します。フォームで変えたばかりの内容は入らないので、先に Save してください
  • .bat はアプリを起動したディレクトリに <command>_<name>.bat という名前で作られます（Workspace の中ではありません）。同じ名前のファイルがあると上書きされます
  • 作るときの Workspace / Dataset Base / Result Base / Env が .bat に書き込まれます

6. Parameterize で繰り返し実行する

同じコマンドを値だけ変えて何回も実行したい場合は、Parameterize を使います。

  1. 元にするオプションを Save しておきます（Parameterize は保存済みの内容から作られます）
  2. サイドバーでその名前の ⚙ を押し、Parameterize を選びます。次の 3 つが作られ、Parameterize のフォームが開きます
    • テンプレート option/parameterize/template/<name>.txt：各オプションが -オプション名=$param.オプション名$ の形になります
    • パラメータデータの CSV <workspace>/<name>.csv：今の値が 1 行だけ入っています
    • Parameterize の保存済みオプション option/parameterize/<name>.txt
  3. CSV に、実行したい回数ぶん行を足して値を変えます。変えない列はテンプレートで固定の値に書き換えてもかまいません
  4. Exec で実行すると、CSV の行ごとにコマンドが実行されます。確認できたら Save し、必要なら Save Shell で .bat にします

unit や cmdParam などの設定は Parameterize を参照してください。

7. Dataset Base / Result Base / Env を使い分けて再利用する

オプションの中ではパスを相対パスで書き、環境で変わる値を ${env.変数名} にしておくと、保存済みオプションを書き換えずに ChangeWorkspace の設定だけで使い回せます。

切り替えるもの向いている場面オプションの書き方
Dataset Base入力データだけが違う（例: 月ごとのデータディレクトリ、テスト用と本番用の入力）入力ファイル（src など）を相対パスで書く
Result Base出力先を分けたい（例: 環境ごと、実行日ごと）出力先（result など）を相対パスで書く
Env接続先・ユーザ・スキーマなどの値が環境ごとに違う（例: 開発 DB とステージング DB）値を ${env.変数名} で書き、環境ごとの .properties を用意する
Workspace保存済みオプションや設定ファイル一式を別にしたい（例: プロジェクトごと）—（保存済みオプション・設定ファイルごと切り替わる）

例: 開発環境で作ったオプションをステージングで使う場合

  1. 開発環境用の env/dev.properties とステージング用の env/staging.properties を用意します
  2. オプションの接続先を ${env.host} などにして Save します
  3. ChangeWorkspace で Env を env/staging.properties、Result Base をステージング用の出力先に変えて confirm を押します
  4. 同じ保存済みオプションをそのまま Exec します。.bat も環境ごとに作る場合は、Save Shell のあとで .bat の名前を変えておいてください（同じ名前だと上書きされるため）

Env ファイルの書き方は Workspace の「環境変数（Env）」、-P 値との使い分けは Parameters (-P) を参照してください。
