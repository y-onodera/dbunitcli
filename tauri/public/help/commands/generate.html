Generate

テンプレートまたは組み込み定義からファイルを生成します。入力データ（srcData）は Dataset Load Form で指定します。generateType は大きく 2 系統に分かれます。

  • テンプレート指定タイプ（txt / xlsx / xls）: template オプションで指定した任意のテンプレートファイルにデータを埋め込みます。出力内容はテンプレート次第で自由に設計できます。
  • 固定成果物タイプ（settings / sql / ddl / xlsxTemplate / xlsxSchema / javaBean / fixedColumnDef）: テーブルのカラム情報等から、決まった形式の成果物ファイルを自動生成します。template は使用しません。組み込みテンプレート以外の出力形式にしたい場合は、generateType=txt と unitSetting を組み合わせて同等の内容を再現してください。

unitSetting の役割 — ddl の組み込み設定とテンプレートで見る

unitSetting は Dataset Settings と同じ JSON 形式の設定ファイルで、入力データをテンプレートに渡す前に整形します。テンプレートは整形後の姿を前提に書けるため、テンプレート側の式が単純になります。ここでは ddl の組み込み設定（sql/ddlSettings.json）と組み込みテンプレート（sql/ddlTemplate.stg）を例に、unitSetting の有無で何が変わるかを示します。これらは Scaffold ダイアログ（generateType=txt のとき unit の上の Scaffold ボタンから開く）で resources/setting/{名前}.json / resources/template/{名前}.stg としてワークスペースへ書き出せ、編集して unitSetting / template に指定して使えます。

1. 入力（記述子データセット） — 1 カラム = 1 行で、テーブルごとに渡されます（例: EMPLOYEE）。

COLUMN_NAMETYPE_NAMECOLUMN_SIZEDECIMAL_DIGITSNULLABLEIS_PKPK_NAMEREMARKSTABLE_REMARKS
EMPLOYEE_IDINTEGER10（空）falsetrue（空）社員ID社員マスタ
EMPLOYEE_NAMEVARCHAR100（空）truefalse（空）氏名社員マスタ
SALARYDECIMAL102truefalse（空）給与社員マスタ

2. unitSetting（ddlSettings.json の抜粋）

{
  "settings": [
    {
      "pattern": {"regex": ".*", "exclude": ["PK"]},
      "separate": [
        { "string": {
            "COLUMN_NAME": "COLUMN_NAME",
            "TYPE_NAME": "TYPE_NAME",
            "COLUMN_SIZE": "COLUMN_SIZE != null && !COLUMN_SIZE.isEmpty() ? COLUMN_SIZE : null",
            "DECIMAL_DIGITS": "DECIMAL_DIGITS != null && !DECIMAL_DIGITS.isEmpty() ? DECIMAL_DIGITS : null" },
          "boolean": { "NULLABLE": "NULLABLE", "IS_PK": "IS_PK" } },
        { "tableName": "PK",
          "filter": ["IS_PK"],
          "string": {"COLUMN_NAME": "COLUMN_NAME", "PK_NAME": "PK_NAME"} }
      ]
    }
  ]
}

これにより次の 3 つの整形が行われます。

  • 空文字を null に変換（COLUMN_SIZE / DECIMAL_DIGITS）: 空欄のカラムをテンプレートの $if(row.COLUMN_SIZE)$ で「値なし」と判定できるようにします。
  • 真偽値へ変換（NULLABLE / IS_PK）: 文字列 "false" を偽として $if(!row.NULLABLE)$ で判定できるようにします。
  • 主キー行を PK サブテーブルへ分割（separate + filter）: テンプレートから dataset.PK.rows として主キーのカラムだけを参照できます。

3. テンプレート（ddlTemplate.stg の抜粋）

ddlType(row) ::= <<$row.TYPE_NAME$$if(row.COLUMN_SIZE)$($row.COLUMN_SIZE$$if(row.DECIMAL_DIGITS)$,$row.DECIMAL_DIGITS$$endif$)$endif$>>
createTable() ::= <<
CREATE TABLE $tableName; format="upper"$ (
    $rows:{row | $row.COLUMN_NAME; format="upper"$ $ddlType(row)$$if(!row.NULLABLE)$ NOT NULL$endif$}; separator=",\n    "$
    $if(dataset.PK.rows)$,CONSTRAINT PK_$tableName; format="upper"$ PRIMARY KEY ($dataset.PK.rows:{row | $row.COLUMN_NAME; format="upper"$}; separator=", "$)
    $endif$
);
>>

テンプレートに書かれているのは「サイズがあれば (サイズ) を付ける」「NOT NULL ならそう出力する」「dataset.PK があれば主キー句を出す」だけで、型の判定や主キー行の抽出といったロジックは unitSetting 側が受け持っています（組み込みテンプレートは PK_NAME があればそれを制約名に使いますが、抜粋では省略しています）。

4. テンプレートから参照できる変数の構造 — unit=table では、テーブルごとに次の変数がテンプレートへ渡されます。unitSetting は主に rows の中身と dataset の構成を変えます。

変数内容unitSetting の影響
tableNameテーブル名（例: EMPLOYEE）なし
columns / primaryKeys / columnsExcludeKeyテーブルのカラム定義なし（入力データ側のカラム定義）
rowsこのテーブルの行（row.列名 で参照）あり。string / boolean で定義した変数が各行に追加される（同名の列は上書き）。元の列は残る
datasetこのテーブルから生成されたテーブルの一覧（dataset.{テーブル名}.rows）あり。separate で分割したサブテーブルが dataset.PK のように追加される

ddl の例（EMPLOYEE）での、テンプレートから見た構造の違いです。

テンプレートを書くうえでの違いは次のとおりです。

テンプレートの記述unitSetting ありunitSetting なし
$if(row.DECIMAL_DIGITS)$値があるときだけ真空文字も値ありとして扱われる可能性がある
$if(!row.NULLABLE)$false のときだけ真（NOT NULL を出力）文字列 "false" も真となり、常に偽になる
$dataset.PK.rows$主キーのカラムだけの一覧参照先が無く、空になる（主キー句を出せない）

つまり unitSetting は「テンプレートが参照する変数の型（文字列 / 真偽値 / null）と、dataset 以下に何が存在するか」を決める役割を持ちます。テンプレートを書くときは、使いたい変数が unitSetting で定義されているかを先に確認してください。

5. レンダリング結果の比較

unitSetting あり（ddlSettings.json）unitSetting なし（generateType=txt で未指定。想定される出力）
CREATE TABLE EMPLOYEE (
    EMPLOYEE_ID INTEGER(10) NOT NULL,
        EMPLOYEE_NAME VARCHAR(100),
        SALARY DECIMAL(10,2)
    ,CONSTRAINT PK_EMPLOYEE PRIMARY KEY (EMPLOYEE_ID)
);
 
CREATE TABLE EMPLOYEE (
    EMPLOYEE_ID INTEGER(10),
        EMPLOYEE_NAME VARCHAR(100),
        SALARY DECIMAL(10,2)
);

unitSetting が無いと、テンプレートが前提とする整形が行われないため、次のようにテンプレートを書いても期待どおりに動きません。

  • NOT NULL が付かない: NULLABLE が文字列のままだと "false" も真として扱われ、$if(!row.NULLABLE)$ が常に偽になります。
  • 主キー句が出ない: PK サブテーブルが作られないため dataset.PK.rows が空になります。
  • 空欄の判定ができない: DECIMAL_DIGITS の空文字が値ありと扱われ、VARCHAR(100,) のような出力になる可能性があります。

unitSetting で変更できる構造（仕様）と組み込みテンプレートでの使われ方

unit=table では、unitSetting はテーブルごとにテンプレートへ渡す前に適用されます。変更できるのは次の 3 点です。

  • rows: 各行の列（値・型）と、残る行・並び順
  • dataset: どのテーブルが存在するか（サブテーブルの追加・名前）と、各テーブルのメタ情報（columns / primaryKeys / columnsExcludeKey）
  • どのテーブルに適用するか（適用範囲）

一方、トップレベルの tableName / columns / primaryKeys / columnsExcludeKey は入力データのままで、unitSetting では変わりません（設定後のメタ情報は dataset.{テーブル名}.columns などで参照します）。

各キーの書式は Dataset Settings と共通です。テンプレート変数への影響は次のとおりです。

キーテンプレート変数への影響組み込みでの使用例
string / boolean / numberrows の各行に変数を追加（同名の列は上書き）。値は JEXL 式で、同じ行の列名を変数として参照できる。型は string / Boolean / BigDecimal になる ddl: COLUMN_SIZE の空文字を null に、NULLABLE / IS_PK を Boolean に変換
javaBean: className / javaType / isBoolean を新規追加
fixedColumnDef: name / length / align / pad を明示（変換なしの最小例）
filter条件（JEXL 式。複数指定は AND）に合う行だけを残すddl: "filter": ["IS_PK"] で主キーの行だけを PK テーブルに残す
separate1 つの入力から複数のテーブルを作り、dataset に追加する。各エントリは独自の string / filter などと tableName（名前）を持てる。tableName を持たないエントリは元のテーブル名のまま ddl: 元のテーブル + PK
xlsxSchema: 元のテーブル + PK + CELLS
tableName / prefix / suffixテーブル名を変更する。rows は「元のテーブル名と同じ名前のテーブル」の行だけなので、元のテーブルを改名すると rows は空になり、行は dataset.{新しい名前}.rows から参照することになるddl / xlsxSchema: サブテーブルの tableName（PK / CELLS）に使用
include / excluderows に残す列を絞り込む（式の評価後に適用されるため、除外する列も式では参照できる）組み込みでは未使用
order行の並び順を指定する組み込みでは未使用
distinct重複行を除去する組み込みでは未使用
keysそのテーブルの主キーを指定した列に置き換える（dataset.{テーブル名}.primaryKeys に反映）組み込みでは未使用
split / innerJoin / outerJoin / fullJoin行の分割・テーブルの結合。仕様は Dataset Settings と共通組み込みでは未使用（テンプレート変数への現れ方は本ページでは未確認）
name / pattern設定を適用するテーブルを選ぶ（変数の構造自体は変えない） ddl / xlsxSchema: "pattern": {"regex": ".*", ...} + exclude。生成したサブテーブル（PK / CELLS）を適用対象から外している
commonSettings全テーブルに適用する（settings は name / pattern に一致したテーブルのみ）javaBean / fixedColumnDef: commonSettings を使用
import別の設定ファイルを取り込んで再利用する組み込みでは未使用

組み込みテンプレートは、この構造のどこを参照しているか

generateTypeテンプレートの参照unitSetting が用意している構造

カスタムテンプレートで同様の構造が必要な場合は、Scaffold で書き出したテンプレートと unitSetting をペアで編集してください。テンプレートだけを変えて、参照する変数・サブテーブルが unitSetting 側に無いと、空の出力や期待と異なる出力になります。

テンプレートを自作・改造するときは、テンプレートに複雑な式を書く前に「unitSetting でカラム値を整形・分割できないか」を検討してください。変数を足したい（例: javaBean の className / javaType）、行を分けたい（例: xlsxSchema の PK / CELLS）といった場合も同じ仕組みで対応できます。組み込み設定は javabean/javaBeanSettings.json、xlsxschema/xlsxSchemaSettings.json、fixedcolumndef/fixedColumnDefSettings.json も Scaffold で書き出せます。

テンプレート指定タイプ

template オプションで指定した任意のテンプレートファイルに、ソースデータを埋め込んで出力します。出力内容はテンプレートの記述次第です。詳細は各 generateType のページ（txt / xlsx・xls）を参照してください。

固定成果物タイプ

テーブルのカラム情報等から、決まった形式の成果物ファイルを組み込みロジック・組み込みテンプレートで自動生成します。template は使用しません。詳細は上記一覧の各 generateType のページを参照してください。
