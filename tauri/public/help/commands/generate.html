Generate

テンプレートまたは組み込み定義からファイルを生成します。入力データ（srcData）は Dataset Load Form で指定します。generateType は大きく 2 系統に分かれます。

  • テンプレート指定タイプ（txt / xlsx / xls）: template オプションで指定した任意のテンプレートファイルにデータを埋め込みます。出力内容はテンプレート次第で自由に設計できます。
  • 固定成果物タイプ（settings / sql / ddl / xlsxTemplate / xlsxSchema / javaBean / fixedColumnDef）: テーブルのカラム情報等から、決まった形式の成果物ファイルを自動生成します。template は使用しません。組み込みテンプレート以外の出力形式にしたい場合は、generateType=txt と unitSetting を組み合わせて同等の内容を再現してください。

unitSetting でできること

unitSetting は Dataset Settings と同じ JSON 形式（settings / commonSettings）の設定ファイルで、入力データをテンプレートへ渡す前の「テーブルの見せ方」を定義します。

  • テンプレート変数の定義: string / boolean に「変数名: 式」を書くと、カラム値から加工した値をテンプレートで使えます（例: 型名から Java の型を判定、空文字を null に変換）。
  • テーブルの分割: pattern で対象テーブルを選び、separate で 1 つのテーブルを複数のサブテーブルに分けられます。filter で行を絞り込めます（例: 主キーのカラムだけを PK テーブルに分ける）。
  • 対象の絞り込み: settings は pattern に一致したテーブルのみ、commonSettings は全テーブルに適用されます。

用途の例: DDL・JavaBean・固定長定義など、unit=table のテンプレートで「1 テーブル（1 カラム = 1 行の記述子データセット）から 1 ファイル」を作るときに、カラム情報をテンプレートが扱いやすい形へ整えます。

unitSetting が無いとできないこと

組み込み設定が自動適用されるのは固定成果物タイプ（ddl / javaBean / xlsxSchema）だけです。generateType=txt で unitSetting を指定しない場合、テーブルは入力データのまま（式による変数の導出も、サブテーブルへの分割もなし）でテンプレートに渡されます。

やりたいことunitSetting なし（txt）unitSetting あり
カラム値から加工した変数をテンプレートで使う（例: TYPE_NAME → javaType、TABLE_NAME → className）できない。テンプレートで参照できるのは入力データの列そのものだけstring / boolean の式で変数を定義でき、テンプレートから参照できる

たとえば Scaffold で書き出した DDL 用のテンプレートは、PK サブテーブルの存在を前提に書かれているため、ddlSettings.json 相当の unitSetting を指定しないと主キー句を出力できません。Scaffold で template と一緒に unitSetting も書き出し、フォームへ反映するのはこのためです。

組み込みファイルの例（Scaffold で書き出されるもの）

Scaffold ダイアログ（generateType=txt のとき unit の上の Scaffold ボタンから開く）は、固定成果物タイプが内部で使っている組み込みの unitSetting を、サンプルとしてワークスペースへ書き出します（resources/setting/{名前}.json）。書き出したファイルを編集し、generate フォームの unitSetting に指定して使います。

target組み込みファイル内容
ddlsql/ddlSettings.json全テーブルを対象に、カラム情報（COLUMN_NAME / TYPE_NAME / COLUMN_SIZE など）を string、NULLABLE / IS_PK を boolean として定義。さらに IS_PK が真の行だけを PK テーブルに分割し、CREATE TABLE の主キー句を作れるようにします。
javaBeanjavabean/javaBeanSettings.jsoncommonSettings で、TABLE_NAME からクラス名（className。先頭大文字化）、TYPE_NAME から Java の型（javaType。VARCHAR→String、INT→Integer など）を式で導出し、javaType == 'Boolean' を isBoolean として定義します。
xlsxSchemaxlsxschema/xlsxSchemaSettings.jsonカラム行（SHEET_NAME / DATA_START / COLUMN_INDEX）、主キー（PK）、セル位置（CELLS）の 3 つのテーブルに分割します。
fixedColumnDeffixedcolumndef/fixedColumnDefSettings.jsoncommonSettings で name / length / align / pad をそのままテンプレート変数にします。固定長のカラム幅定義を組み立てる最小構成の例です。

例（ddlSettings.json の抜粋。主キーのカラムだけを PK テーブルに切り出す部分）:

{
  "settings": [
    {
      "pattern": {"regex": ".*", "exclude": ["PK"]},
      "separate": [
        { "string": {"COLUMN_NAME": "COLUMN_NAME", "TYPE_NAME": "TYPE_NAME"},
          "boolean": {"NULLABLE": "NULLABLE", "IS_PK": "IS_PK"} },
        { "tableName": "PK",
          "filter": ["IS_PK"],
          "string": {"COLUMN_NAME": "COLUMN_NAME", "PK_NAME": "PK_NAME"} }
      ]
    }
  ]
}

テンプレート指定タイプ

template オプションで指定した任意のテンプレートファイルに、ソースデータを埋め込んで出力します。出力内容はテンプレートの記述次第です。詳細は各 generateType のページ（txt / xlsx・xls）を参照してください。

固定成果物タイプ

テーブルのカラム情報等から、決まった形式の成果物ファイルを組み込みロジック・組み込みテンプレートで自動生成します。template は使用しません。詳細は上記一覧の各 generateType のページを参照してください。
