Generate

テンプレートまたは組み込み定義からファイルを生成します。入力データ（srcData）は Dataset Load Form で指定します。generateType は大きく 2 系統に分かれます。

  • テンプレート指定タイプ（txt / xlsx / xls）: template オプションで指定した任意のテンプレートファイルにデータを埋め込みます。出力内容はテンプレート次第で自由に設計できます。
  • 固定成果物タイプ（settings / sql / ddl / xlsxTemplate / xlsxSchema / javaBean / fixedColumnDef）: テーブルのカラム情報等から、決まった形式の成果物ファイルを自動生成します。template は使用しません。組み込みテンプレート以外の出力形式にしたい場合は、generateType=txt と unitSetting を組み合わせて同等の内容を再現してください。

unitSetting でできること（仕様）

unitSetting は Dataset Settings と同じ JSON 形式（settings / commonSettings）の設定ファイルです。unit=table では、テーブルごとにテンプレートへ渡す前に適用され、テンプレートから見えるデータの形を次の 3 点で変えられます。

  • rows: 各行に持たせる列（値・型）、残す行、並び順
  • dataset: どのテーブルがあるか（サブテーブルの追加・名前）と、各テーブルのカラム情報
  • 適用範囲: どのテーブルに適用するか

テンプレートは整形後のデータを前提に書けるため、判定や抽出のロジックを unitSetting に寄せると、テンプレート側の式が単純になります。

注意点

  • 値の型: 設定がない列の値はすべて文字列です。文字列の "false" や空文字 "" もテンプレートの $if(...)$ では真になります。真偽や「空欄は値なし」で判定したい列は、boolean や ? : で null に変換してください。
  • 存在しない列: 入力に無い列名を式で参照するとエラーになります。
  • サブテーブルへの再適用: pattern が .* のままだと、separate で作ったサブテーブルにも設定が再度適用され、行が重複します。サブテーブル名は exclude で除外してください（組み込みの ddl / xlsxSchema がそうしています）。
  • split と結合: split で分割しても、dataset には最後の断片だけが残ります。innerJoin / outerJoin / fullJoin の結果は dataset に現れません。どちらもテンプレート生成には向きません。

例 1: ddl の組み込み設定とテンプレートを読み解く

ddl の組み込み設定（sql/ddlSettings.json）とテンプレート（sql/ddlTemplate.stg）で、unitSetting の有無によるテンプレートの動きの違いを示します。どちらも Scaffold ダイアログ（generateType=txt のとき unit の上の Scaffold ボタンから開く）でワークスペースに書き出して編集でき、フォームの unitSetting / template に指定して使います。

1. 入力（記述子データセット） — 1 カラム = 1 行で、テーブルごとに渡されます（例: EMPLOYEE）。以降の出力例は、この入力を CSV にして実際に生成した結果です。

COLUMN_NAMETYPE_NAMECOLUMN_SIZEDECIMAL_DIGITSNULLABLEIS_PKPK_NAMEREMARKSTABLE_REMARKS
EMPLOYEE_IDINTEGER10（空）falsetruePK_EMPLOYEE社員ID社員マスタ
EMPLOYEE_NAMEVARCHAR100（空）truefalse（空）氏名社員マスタ
SALARYDECIMAL102truefalse（空）給与社員マスタ

2. unitSetting（ddlSettings.json の抜粋）

{
  "settings": [
    {
      "pattern": {"regex": ".*", "exclude": ["PK"]},
      "separate": [
        { "string": {
            "COLUMN_NAME": "COLUMN_NAME",
            "TYPE_NAME": "TYPE_NAME",
            "COLUMN_SIZE": "COLUMN_SIZE != null && !COLUMN_SIZE.isEmpty() ? COLUMN_SIZE : null",
            "DECIMAL_DIGITS": "DECIMAL_DIGITS != null && !DECIMAL_DIGITS.isEmpty() ? DECIMAL_DIGITS : null" },
          "boolean": { "NULLABLE": "NULLABLE", "IS_PK": "IS_PK" } },
        { "tableName": "PK",
          "filter": ["IS_PK"],
          "string": {"COLUMN_NAME": "COLUMN_NAME", "PK_NAME": "PK_NAME"} }
      ]
    }
  ]
}

これにより次の 3 つの整形が行われます。

  • 空文字を null に変換（COLUMN_SIZE / DECIMAL_DIGITS）: 空欄のカラムをテンプレートの $if(row.COLUMN_SIZE)$ で「値なし」と判定できるようにします。
  • 真偽値へ変換（NULLABLE / IS_PK）: 文字列 "false" を偽として $if(!row.NULLABLE)$ で判定できるようにします。
  • 主キー行を PK サブテーブルへ分割（separate + filter）: テンプレートから dataset.PK.rows として主キーのカラムだけを参照できます。

3. テンプレート（ddlTemplate.stg の抜粋）

ddlType(row) ::= <<$row.TYPE_NAME$$if(row.COLUMN_SIZE)$($row.COLUMN_SIZE$$if(row.DECIMAL_DIGITS)$,$row.DECIMAL_DIGITS$$endif$)$endif$>>
createTable() ::= <<
CREATE TABLE $tableName; format="upper"$ (
    $rows:{row | $row.COLUMN_NAME; format="upper"$ $ddlType(row)$$if(!row.NULLABLE)$ NOT NULL$endif$}; separator=",\n    "$
    $if(dataset.PK.rows)$,CONSTRAINT PK_$tableName; format="upper"$ PRIMARY KEY ($dataset.PK.rows:{row | $row.COLUMN_NAME; format="upper"$}; separator=", "$)
    $endif$
);
>>

テンプレートに書かれているのは「サイズがあれば (サイズ) を付ける」「NOT NULL ならそう出力する」「dataset.PK があれば主キー句を出す」だけで、型の判定や主キー行の抽出といったロジックは unitSetting 側が受け持っています（組み込みテンプレートは PK_NAME があればそれを制約名に使いますが、抜粋では省略しています）。

5. レンダリング結果の比較

unitSetting あり（ddlSettings.json）unitSetting なし（generateType=txt で未指定）
CREATE TABLE EMPLOYEE (
    EMPLOYEE_ID INTEGER(10) NOT NULL,
        EMPLOYEE_NAME VARCHAR(100),
        SALARY DECIMAL(10,2)
    ,CONSTRAINT PK_EMPLOYEE PRIMARY KEY (EMPLOYEE_ID)
);
 
CREATE TABLE EMPLOYEE (
    EMPLOYEE_ID INTEGER(10,),
        EMPLOYEE_NAME VARCHAR(100,),
        SALARY DECIMAL(10,2)
);

unitSetting が無いと、テンプレートが前提とする整形が行われないため、次のようにテンプレートを書いても期待どおりに動きません。

  • NOT NULL が付かない（EMPLOYEE_ID に付かない）: NULLABLE が文字列のままだと "false" も真として扱われ、$if(!row.NULLABLE)$ が常に偽になります。
  • 主キー句が出ない: PK サブテーブルが作られないため dataset.PK.rows が空になります。
  • 空欄の判定ができない: DECIMAL_DIGITS の空文字が値ありと扱われ、INTEGER(10,) や VARCHAR(100,) のように不正な型指定が出力されます。

例 2: 組み込みを改造する（コメントの既定値を追加）

組み込みの DDL では、備考（REMARKS）が空のカラムは COMMENT ON COLUMN ... IS '' と空のコメントになります。ここでは、備考が空ならカラム名をコメントにするように、unitSetting とテンプレートの両方に手を加えます。

1. unitSetting: 判定を設定側に追加する — ddlSettings.json の最初の separate の string に、COMMENT_TEXT を 1 行足します。

"string": {
  "COLUMN_NAME": "COLUMN_NAME",
  "TYPE_NAME": "TYPE_NAME",
  ... （既存の定義）
  "COMMENT_TEXT": "REMARKS != null && !REMARKS.isEmpty() ? REMARKS : COLUMN_NAME"
}

2. テンプレート: 追加した変数を参照する — ddlTemplate.stg の commentOnColumns() を、COMMENT_TEXT を使う形に書き換えます。

commentOnColumns() ::= <<
$rows:{row | COMMENT ON COLUMN $tableName; format="upper"$.$row.COLUMN_NAME; format="upper"$ IS '$row.COMMENT_TEXT$';
}$
>>

3. 結果 — 入力の SALARY の備考が空のとき:

組み込みのまま改造後
COMMENT ON COLUMN EMPLOYEE.EMPLOYEE_ID IS '社員ID';
COMMENT ON COLUMN EMPLOYEE.EMPLOYEE_NAME IS '氏名';
COMMENT ON COLUMN EMPLOYEE.SALARY IS '';
 
COMMENT ON COLUMN EMPLOYEE.EMPLOYEE_ID IS '社員ID';
COMMENT ON COLUMN EMPLOYEE.EMPLOYEE_NAME IS '氏名';
COMMENT ON COLUMN EMPLOYEE.SALARY IS 'SALARY';

テンプレートだけを書き換えて unitSetting に COMMENT_TEXT を足さないと、テンプレートが参照する変数が存在しないため、コメントはすべて空（IS ''）になります。テンプレートが参照する変数・サブテーブルは、対応する unitSetting とペアで編集してください。書き出した設定とテンプレートは、フォームの unitSetting / template に指定すると組み込みの代わりに使われます。

手を加える範囲の目安は次のとおりです。

  • 表示を変えるだけ（文言・並び・インデント）: テンプレートだけを編集する。
  • 判定や変換を足したい（空欄の既定値、型の読み替え、条件分岐の元になるフラグ）: unitSetting に string / boolean を足し、テンプレートで参照する。
  • 一部の行を別に扱いたい（主キーだけ、特定の列だけ）: unitSetting の separate + filter でサブテーブルを作り、テンプレートで dataset.{名前}.rows を参照する。

テンプレート指定タイプ

template オプションで指定した任意のテンプレートファイルに、ソースデータを埋め込んで出力します。出力内容はテンプレートの記述次第です。詳細は各 generateType のページ（txt / xlsx・xls）を参照してください。

固定成果物タイプ

テーブルのカラム情報等から、決まった形式の成果物ファイルを組み込みロジック・組み込みテンプレートで自動生成します。template は使用しません。詳細は上記一覧の各 generateType のページを参照してください。
