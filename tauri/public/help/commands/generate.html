Generate

入力データ（srcData）からファイルを生成します。generateType は次の 2 系統に分かれます。

  • テンプレート指定タイプ（txt / xlsx / xls）: template に指定したテンプレートにデータを埋め込みます。出力内容はテンプレート次第で自由に作れます
  • 固定成果物タイプ（settings / sql / ddl / xlsxTemplate / xlsxSchema / javaBean / fixedColumnDef）: テーブルのカラム情報などから、決まった形式のファイルを生成します。template は使いません

固定成果物タイプの出力を変えたい場合は、Scaffold で組み込みテンプレートを書き出し、generateType=txt で生成してください。

並列処理（parallel）

parallel は、srcData の srcType が file / dir / none 以外のとき、または unit=record のとき（srcType が none の場合を除く）に表示されます。指定したスレッド数で次の処理を並列にします。

処理並列の仕方
srcData の読み込みソース（ファイル・SQL など）ごとに並列に読み込む。条件は Convert の並列読込と同じ（Result Form を参照）
unit=record の出力行ごとの出力を並列にする。データセット全体をメモリに読み込まずに出力するため、1 行ごとに 1 ブックを作る xlsx / xls で特に効果がある
unit=table の出力テーブルごとの出力を並列にする（txt / xlsx / xls と、unit が table 固定の固定成果物タイプ）。xlsx / xls で lazyLoad が OFF のときは、全件を読み込んでから出力だけを並列にする

次の場合は、unit=table の出力を逐次で処理します。

  • 出力するテーブルが 1 つだけの場合
  • srcData の設定ファイルで join または件数分割（split）を使っている場合（lazyLoad が OFF の xlsx / xls を除く）

注意:

  • ファイルは並列に書かれるため、書き込まれる順番は決まりません。各ファイルの内容は逐次処理と同じです
  • resultPath に行やテーブルを区別する値がなく、複数の行・テーブルが同じファイルに出力される場合、別のソースから来た内容のどれが残るかは決まりません
  • srcType が table / sql の場合は、並列数まで DB 接続を同時に使います
  • 並列数を増やすと、同時に処理する行・テーブルの分だけメモリ使用量も増えます。srcData の includeMetaData が ON の unit=record では、テーブル全体を保持します
  • Parameterize の並列実行の中では、空欄のときは逐次になります
