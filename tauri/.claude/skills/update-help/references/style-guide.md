# ヘルプ執筆ガイド（tauri/public/help）

ヘルプ HTML の文体・想定読者・章立てを揃えるための基準。新規作成・修正のどちらにも適用する。ディレクトリ構成とリンクの規則は `../SKILL.md` に従う。

## 1. 想定読者

**GUI で作業する利用者**を主な読者とする。

- 知っている前提: DB・SQL・CSV・Excel の基礎、ファイルとディレクトリの概念
- 知らない前提: DBUnit・StringTemplate・JEXL・jxls の詳細、アプリの内部構成（sidecar・Java API・スレッドの割り当て）

書き方の原則:

- 画面のどこで設定し、何が変わるかを書く。「なぜそう動くか」は、利用者の判断に必要な場合だけ書く
- 内部実装（`connection.createTable()` などの API 名、sidecar、スレッドの割り当て）は書かない。必要なら利用者から見える影響に言い換える
  - 悪い例: `connection.createDataSet().getTable()` を使用する
  - 良い例: 接続先スキーマ全体を読み込むため、カラム型の判定が正確になるが、スキーマが大きいと開始が遅くなる
- CLI の引数表記（`-src.srcType=csv`）は、例や CLI に固有の話をする場合に限って使う。本文ではフォームに表示される項目名で書く

## 2. 文体

| 対象 | 文体 | 例 |
|---|---|---|
| 本文・手順・注意 | です・ます調 | 区切り文字を指定します。 |
| 表のセル | 体言止めまたは常体。1 文なら句点なし。2 文以上は「。」で区切り、最後の文にも付ける | 出力ファイルの文字コード |
| 箇条書き（項目の列挙） | 表のセルと同じ | 主キーを keys に引き継ぐ |
| 箇条書き（手順） | です・ます調 | Execute を押します。 |
| 見出し | 体言止め | 固有オプション |

- 利用者への依頼は「〜してください」に揃える（「〜すること」「〜を推奨」は使わない）
- 1 つの段落に詰め込まない。条件・例外が 3 つ以上あれば箇条書きか表にする
- 数字と英単語の前後には半角スペースを入れる（例: `1 行目`、`CSV ファイル`）。これは既存の表記に合わせたもの

## 3. 表記・用語

### 用語集

| 使う表記 | 使わない表記 | 補足 |
|---|---|---|
| 雛型 | ひな型、雛形 | |
| デフォルト | 既定、既定値 | 表の列名も「デフォルト」 |
| JEXL | JeXL | Apache Commons JEXL の正式表記 |
| 文字コード | エンコーディング | 項目名 `encoding` はそのまま |
| ヘッダ / ユーザ | ヘッダー / ユーザー | 画面上部の領域も「ヘッダ」。パラメータ・フッター・ディレクトリなどほかの語は現状の表記のまま |
| ディレクトリ | フォルダ | |
| Workspace | ワークスペース | 画面の表記に合わせる |
| Excel | Xlsx（一般名詞として） | 項目名・ダイアログ名（`xlsxSchema`、Xlsx Schema）はそのまま |
| ON / OFF | true / false、有効 / 無効 | チェックボックスの項目。JSON の値を説明する場合は `true` / `false` |

### 「パラメータ」の呼び分け

| 指すもの | 表記 |
|---|---|
| サイドバーに並ぶ、保存したフォームの内容（`option/<command>/<name>.txt`） | 保存済みオプション |
| Edit Parameters (-P) で渡す値 | -P 値 |
| Parameterize の paramData の内容 | パラメータデータ |

### 項目名・値・UI 名の書き方

- オプション名・値・ファイル名・パスは `<code>` で囲む（例: `<code>srcType</code>`、`<code>csv</code>`）
- ボタン名・ダイアログ名は画面の英語表記をそのまま書き、`<code>` は付けない（例: Execute を押します）
- 種類を選ぶオプションは、項目名で呼ぶ（`srcType`、`resultType`、`targetType`、`scriptType`、`generateType`）。「Source Type」「ソースタイプ」とは書かない

## 4. 表の書き方

オプションの表は、次の列順に揃える。不要な列は省いてよい。

| 列 | 内容 |
|---|---|
| 項目 | `<code>` 付きの項目名。必須なら項目名の後ろに「（必須）」 |
| 説明 | 何を指定するか、指定すると何が変わるか |
| デフォルト | 値。空欄がデフォルトなら「（空）」、なしなら「—」 |

- 列名は「項目」に揃える（「オプション」「フィールド」「設定項目」は使わない）
- デフォルト値は「デフォルト」列に書き、説明の中には「（デフォルト: X）」と書かない
- 値の一覧の表は「値 / 説明」の 2 列にする

## 5. ページ共通の構成

```html
<p><a href="（戻り先）">&larr; （戻り先のページ名）に戻る</a></p>
<h1>（ページ名）</h1>
<p>（概要: 1〜3 文）</p>
（本文の h2）
<h2 id="section-related">関連</h2>
```

- `<title>` は `ヘルプ - （h1 と同じ文字列）` にする
- h1 は画面の表記に合わせる（ダイアログ名・セクション名は英語のまま）
- types ページの h1 は `項目名: 値` にする（例: `srcType: csv`、`generateType: ddl`、`srcType: xls / xlsx`）。補足の括弧書きは付けない
- 概要には「何のための画面・項目か」と「どこから開くか」を書く
- 戻り先は、types ページと `commands/generate/unitSetting.html` なら親ページ、それ以外は `index.html`（ヘルプ一覧）
- h2 には `id="section-xxx"` を付ける。h2 が 6 個以上あるページは、h1 の直後に目次を置く
- 関連ページは末尾の「関連」にまとめる。本文中のリンクは説明に必要な箇所だけに付ける
- 注意事項の見出しは「注意」に揃える

## 6. ヘルプ一覧（index.html）と使い方ページ

GUI のヘルプボタンから開くページ（画面の要素ごとのページ）とは別に、index から順に読める導線を用意する。

index は次の順に、すべてのページへのリンクを並べる。

1. **基本的な使い方** — `guide/` のページ。Workspace の選択 → コマンドの作成 → Exec → Save → Save Shell → Parameterize → 環境ごとの使い回し、の流れを説明する
2. **コマンド** — `commands/` の 5 コマンド
3. **画面・設定の詳細** — `sections/`、`dialogs/`、`reference/` のページ。入力・出力・テンプレート・接続・Workspace・-P などのまとまりごとに見出しを分ける

使い方ページと、画面の要素ごとのページの役割分担:

- 使い方ページ: 作業の流れを手順で書く。各画面の項目の説明は書かず、その画面のページへリンクする
- 画面の要素ごとのページ（例: `dialogs/workspace.html`）: その画面の項目・ボタン・挙動だけを書く。作業の流れは使い方ページへリンクする

## 7. ページ種別ごとの章立て

括弧内の章は、該当する内容がなければ省く。順序は変えない。

| 種別 | 対象 | 章立て（h2） |
|---|---|---|
| 使い方 | `guide/*.html` | 手順ごとの h2（「1. 〜する」の形）→ 関連 |
| コマンド | `commands/*.html` | オプション → 〈項目名〉一覧 →（並列処理）→（使用例）→ 関連 |
| コマンドの type | `commands/*/types/*.html` | 固有オプション →（項目ごとの詳細）→ 出力例（compare は比較結果の形式、run は設定例）→（注意）→ 関連 |
| フォームのセクション | `sections/*.html` | 設定項目 →（項目ごとの詳細）→（例）→（注意）→ 関連 |
| セクションの type | `sections/*/types/*.html` | 読み込み対象（出力は「出力先」）→ 固有オプション → 入出力例 →（注意） |
| 生成ダイアログ | `dialogs/*-generate.html` | できること → 入力 → 操作の流れ → 生成例 →（生成ルール）→ 注意 → 関連 |
| 編集ダイアログ | `dialogs/*-edit.html`、`sql-editor`、`xlsx-*-setting` など | 開き方 → 記述内容（設定項目）→（記述例）→（操作）→（保存）→（注意）→ 関連 |
| 設定ファイルの書式 | `dialogs/dataset-settings.html` など | 全体構造 → フィールド →（共通設定・上書き規則）→ 記述例 → 関連 |
| リファレンス | `reference/*.html` | 構文・項目 → 例 → 関連 |

補足:

- 「セクションの type」の「読み込み対象」には、`src` に指定するもの・テーブル名の決まり方・ほかの章に当てはまらない制約を表にまとめる
- 例は「入力 → 指定 → 結果」の順に `<pre>` で示す。指定は `項目 = 値` の形にそろえる

## 8. 内容の置き場所（重複させない）

同じ説明を複数のページに書かない。詳しく書くページを 1 つ決め、他のページは 1 文の要約とリンクにする。

| 内容 | 詳しく書くページ |
|---|---|
| Dataset Settings のフィールド | `dialogs/dataset-setting.html`（`dataset-settings.html` は全体構造と一覧表だけ） |
| JEXL 式 | `dialogs/dataset-setting.html` |
| StringTemplate の書式 | `reference/st4.html`（`sections/template.html` は設定項目と簡単な例だけ） |
| 並列処理の条件 | `sections/result-form.html`（コマンドのページは差分だけ） |
| Env と -P の使い分け | `dialogs/parameters.html` |
| 作業の流れ（Workspace の選択から再利用まで） | `guide/` の使い方ページ |
| ファイル選択と基準ディレクトリ | `dialogs/workspace.html` |
| 組み込みテンプレートのカスタマイズ方法 | `dialogs/txt-template-generate.html`（固定成果物の type ページは 1 文とリンク） |
